# 满满音乐 — 功能说明

全部功能都是**纯客户端实现**：不需要自建服务器、不需要买云主机，
只用免费的公共服务做中转。架构上只有三处外部依赖：

| 用途 | 服务 | 是否需要注册 |
| --- | --- | --- |
| 哔哩哔哩登录 / 取音源 | B 站官方 web 接口 | 用你自己的 B 站账号 |
| 一起听同步 | ntfy.sh（公共 pub/sub） | 不需要 |
| 检查更新 | GitHub Releases API | 不需要 |

---

## 界面结构

底部只有三个入口：

```
首页        一起听        设置
```

**首页**（默认打开）

```
┌─────────────────────────────┐
│  [ 搜索歌曲、UP主        ] ⌃ │  ← 右上角 ⌃ 收起/展开账号卡
├─────────────────────────────┤
│  [头像] 昵称                 │  ← 账号卡：未登录显示「登录解锁高音质」
│         已登录 · 高音质已开启 │
├─────────────────────────────┤
│   ( 历史播放 | 我的歌单 )     │  ← 双分栏，左右滑动或点击切换
├─────────────────────────────┤
│  封面  歌名                  │
│        UP 主          3 分钟前│
│  封面  歌名                  │
│        UP 主         12 分钟前│
└─────────────────────────────┘
```

- **历史播放**是默认分栏，记录你真正播放过的歌
  - 点击播放
  - **长按进入多选**，可全选、批量删除；单条也能删
  - 底部有「清空播放记录」
- **我的歌单**是「我喜欢」+ 你自建的所有歌单
  - 点击进入歌单
  - **长按**可清空歌曲或删除整个歌单
- 两栏之间可以左右滑动，也可以点标题切换

## 1. 哔哩哔哩登录

**为什么值得登录**：不登录时 B 站只给最低音质；登录后即可拿到更高音质
（Hi-Res / 无损需要账号本身有大会员权益，但**没有会员登录也有用**）。

**什么时候会看到登录引导**：

- 首次进入首页时自动弹一次，说明登录是为了音质
- 选择「先随便听听」后**不再打扰**，之后可以点首页账号卡或一起听页再登录

**怎么登录**：点「去登录」→ 显示 B 站官方二维码 → 用 B 站手机客户端扫一扫。

> 二维码是官方接口返回的那个二维码，等同你自己在电脑网页上扫码登录。
> 登录凭证（Cookie）只存在本机 `shared_preferences`，不上传任何服务器，
> 随时可在「设置 → 哔哩哔哩账号」退出并清除。

**音质策略**：登录后请求 `fnval=4048`（含 Hi-Res / 无损 / 杜比），
被拒或失败时**静默回退** `fnval=16`，不影响正常播放。

### 关于「别把号封了」

代码刻意规避了所有高风险行为：

| 做法 | 说明 |
| --- | --- |
| 只用官方 web 接口 | 与你在浏览器里登录、看视频用的接口完全一致 |
| 只在用户点击时发请求 | 没有后台轮询、没有定时任务、没有批量抓取 |
| 不做任何写操作 | 不点赞、不投币、不收藏、不评论、不改任何数据 |
| 收藏夹只读 | `fav/resource/list` 是纯查询，每页 20 条、翻页有间隔 |
| 好友列表只拉一页 | 只在打开「一起听」时拉 20 个，不翻页 |

## 2. 分享链接直接播放

**不需要去设置里点任何开关**。App 启动时会静默读一次剪贴板：

- 剪贴板里是 B 站视频链接（含 `b23.tv` 短链、微信/QQ 分享出来的整段文字）→ 自动解析播放
- 剪贴板里是满满音乐分享链接 → 自动按分享内容处理
- 都不是 → 什么都不做，不弹任何提示

另外也支持系统的「分享到满满音乐」和 `manman://` 深链唤起。

## 3. 收藏夹导入与同步

**位置**：设置 → 哔哩哔哩账号 → 导入收藏夹

登录后可把你 B 站的收藏夹搬过来，变成一个本地歌单，出现在首页「我的歌单」里。

### 导入之后会跟着 B 站走

导入一次就会记住这个收藏夹，之后：

| B 站那边 | 这边 |
| --- | --- |
| 收藏夹里加视频 | 打开收藏夹页会补进来，也可点「同步」手动拉 |
| 收藏夹里删视频 | 本地对应条目会被移除 |
| 把整个收藏夹删了 | 本地歌单自动删除 |
| 收藏夹改名 | 本地继续用原来的歌单名，不跳来跳去 |

- 再点一次同一个收藏夹的「同步」不会报错，而是做增量更新
- 顶部有「全部同步」，一次把所有已导入的收藏夹对齐
- 没导入过的收藏夹完全不管
- 「移除」只删本地歌单，B 站上的收藏夹不受影响

### 删除歌单

在首页「我的歌单」里**长按**任意歌单，会弹出两个选项：

- **清空歌曲**：保留歌单，只把里面的歌删掉
- **删除整个歌单**：歌单和歌一起删掉（来自收藏夹的会同时解除关联，B 站不受影响）

### 一个技术细节

B 站收藏夹接口只返回 `aid` / `bvid`，**不返回 `cid`**，而取音频流必须要 `cid`。
这不是收藏夹的问题，但会导致「导入的歌播不了、报 source error」。
现在改成在取流时按需补查 `cid` 并缓存，已经导入的旧数据也一并修好了。

## 4. 一起听

**位置**：底部「一起听」

### 不用建房，打开 App 就上线

**打开 App 就自动上线**，不需要点「创建房间」，也不需要输入房间号。

你的房间号是自动派生的：

- 已登录 B 站 → `bili_<你的UID>`，好友知道你的 UID 就能找到你
- 未登录 → 本地随机生成的 id（换手机就变了）

**如果想手动控制**：设置 → 「打开 App 自动上线一起听」关掉（默认是开的）。
关掉后，在一起听页顶部会出现「上线 / 下线」按钮。
手动点了下线，就不会被偷偷重新拉起。

### 名单是空的，需要你自己加人

一开始名单里**什么都没有**。点「添加 / 选择」进入勾选页，
从你关注的人里挑出真正会一起听歌的那几个。

- 已加进来的人：右侧 ✕ 或长按可以移除
- 没加进来的人：不会被探测，也不会出现在列表里

> 之前是把「我关注的人」全部列出来，几十个 UP 主一起探测又慢又乱，
> 绝大多数还根本不会一起听歌，所以改成了手动维护名单。

### 能看到名单里的人在听什么

- 正在听歌的人：显示「正在听《歌名》」+ 绿点高亮，右边有「一起听」按钮
- 没在听歌的人：置灰，点击提示「TA 现在没在听歌」

点「一起听」即加入对方房间，之后对方的切歌、暂停、拖动进度你都会自动跟随。

### 同步怎么做的

- 房主每 3 秒广播一次当前状态（歌、进度、是否在播）
- 听众收到后按消息里的时间戳**补偿网络延迟**
- 进度偏差超过 1.5 秒才跳转，避免抖动
- 断线 4 秒自动重连，90 秒没动静的成员自动清理

### 两个诚实的限制

1. B 站没有公开的「互关好友」接口，勾选页里能选的是**我关注的人**，不是严格互关
2. 必须**双方都装了满满音乐、且都处于上线状态**才能互相看到。
   对方没上线就不会广播，你看到的就是「没在听歌」

## 5. 把歌分享给好友

播放页可以把当前歌曲分享到 QQ / 微信。

分享出去的是一条 `manman://play?d=<base64url>` 链接，**歌曲信息内嵌在链接里**，
所以对方不需要任何服务器就能还原出这首歌。对方装了满满音乐点开即播；
没装的话链接不会生效（但也不会报错）。

## 6. 检查更新

**位置**：设置 → 检查更新

查的是本项目自己的 GitHub Release（`m-rui001/bobomusic`），不会去查上游项目。
有新版本时显示版本号和更新说明，点「下载安装包」直接下 APK 覆盖安装，
歌单和登录状态都会保留。

## 技术备注

| 项目 | 说明 |
| --- | --- |
| 一起听中继 | ntfy.sh，订阅 `GET /{topic}/json`，发布 `POST /{topic}` |
| topic 命名 | `manman_party_<roomId>`，带前缀隔离 |
| 好友在听探测 | `GET /{topic}/json?poll=1&since=60s` 一次性拉取，**不做定时轮询** |
| 分享载荷 | base64url 编码，字段压缩为 `t/n/a/c/d/p/i/o/f` |
| 深链 | `app_links` 处理 `manman://`，`MethodChannel("manman/share")` 处理系统分享 |
| 历史播放 | `shared_preferences` 持久化，最多 100 条，同曲去重提前 |
| 一起听名单 | `shared_preferences`，默认空，只有名单里的人会被探测 |
| 自动上线 | 默认开启，`shared_preferences` key `manman_party_auto_online` |
| 收藏夹绑定 | `shared_preferences` key `manman_fav_bindings`，记录 favId → 本地歌单 |
| 缺失 cid | 取流时按 `x/web-interface/view` 补查，带内存缓存与并发去重 |
| 登录方式 | 内嵌官方登录页（`flutter_inappwebview`），App 不接触密码 |

> 之前评估过用公共 MQTT broker（hivemq / emqx / mosquitto）做一起听中继，
> 实测在当前网络下**跨客户端无法转发消息**（单客户端回环正常），故改用 ntfy.sh。
