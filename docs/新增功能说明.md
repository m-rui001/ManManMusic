# 满满音乐 — 新增功能说明

本次为「满满音乐」增加了 6 组功能，全部是**纯客户端实现**：
不需要自建服务器、不需要花钱买云主机，只用免费的公共服务做中转。

---

## 1. 哔哩哔哩扫码登录（拿高音质）

**位置**：设置 → 哔哩哔哩账号

- 使用哔哩哔哩**官方网页版扫码登录接口**（`passport.bilibili.com`），
  二维码就是官方那个二维码，等同你自己在电脑上扫码登录。
- 登录凭证（Cookie）只保存在**本机**（`shared_preferences`），
  不上传任何服务器，随时可在设置里退出登录一键清除。
- 登录后请求音轨时使用 `fnval=4048`，可拿到 **Hi-Res 无损 / 杜比全景声**
  （需要你的账号本身有大会员权益）。
- 未登录、或高音质请求被拒时，**自动静默退回** `fnval=16` 的普通音轨，
  不影响原有播放能力。

### 关于「别把号封了」

代码刻意规避了所有高风险行为：

| 做法 | 说明 |
| --- | --- |
| 只用官方 web 接口 | 与你在浏览器里登录、看视频用的接口完全一致 |
| 只在用户点击时发请求 | 没有任何后台轮询、定时任务、批量抓取 |
| 不做任何写操作 | 不点赞、不投币、不收藏、不评论、不修改任何数据 |
| 收藏夹只读 | `fav/resource/list` 是纯查询接口，每页 20 条、翻页有间隔 |
| 保留正常指纹 | 复用项目已有的 `buvid3/buvid4` SPI 与 `bili_ticket` 签名 |
| 不并发狂刷 | 导入是一次性顺序请求，正常人手动操作也会这样 |

> 客观说明：任何第三方客户端都无法 100% 保证不被风控，
> 但上述做法已经等价于「你自己用浏览器操作」，风险与手动使用网页版相当。

## 2. 直接打开 B 站分享链接 / 微信 QQ 分享的内容

**位置**：
- 设置 → 打开分享链接（从剪贴板粘贴）
- 在微信 / QQ 里长按消息 → 分享 → 选择「满满音乐」
- 直接点 `bilibili.com/video/BVxxx` 链接时选择用满满音乐打开

支持的输入形态：
- 完整链接：`https://www.bilibili.com/video/BV1xx411c7mD?p=2`
- 短链：`https://b23.tv/xxxxxxx`（自动跟随跳转解析）
- 微信/QQ 的一整段分享文案（自动从中抠出链接，并去掉尾部中文标点）
- av 号：`/video/av170001`

多分 P 视频会弹出选 P 面板，选完直接开始播放。

## 3. 一键导入 B 站收藏夹

**位置**：设置 → 哔哩哔哩账号 → 从收藏夹导入歌单

- 读取你账号下的全部收藏夹（`fav/folder/created/list-all`）
- 每个收藏夹可以单独「导入」，生成一个同名歌单：`收藏夹_<收藏夹名>`
- 分页拉取（每页 20 条），自动去重，导入完成后歌单会出现在首页歌单列表
- 全程只读，不修改你的收藏夹

## 5. 把正在播放的音乐分享给 QQ / 微信好友

**位置**：播放页底部 → 分享图标

分享出去的内容是**一段可读文案 + 一个链接**：

```
🎵 小明在「满满音乐」分享了《某首歌》 - 某UP主
复制这条消息打开满满音乐即可播放：
manman://play?d=<压缩后的歌曲信息>
```

- 歌曲信息（ID / 歌名 / UP 主 / 封面 / 时长 / 当前进度）全部
  **base64url 编码内嵌在链接里**，不依赖任何服务器存数据
- 好友把消息复制回满满音乐（设置 → 打开分享链接），
  或直接点链接（Android 已注册 `manman://` scheme），就会打开同一首歌，
  并跳到分享者当时听到的进度，接着听
- 也可以选「复制歌曲信息」自己粘贴到任意聊天窗口

## 6. 一起听（看好友在听什么、同步进度）

**位置**：设置 → 一起听

### 怎么用

1. 你点「创建房间（我做房主）」，得到 6 位房间号
2. 把房间号发给好友（或直接在播放页分享 → 邀请一起听，链接里带房间号）
3. 好友在「一起听」里输入房间号加入

### 效果

- 房主**切歌、暂停/播放、拖动进度**，好友自动跟随
- 进度会做**网络延迟补偿**（按消息里的时间戳推算真实位置），
  偏差小于 1.5 秒时不做纠正，避免抖动
- 双方都能看到**在线成员**列表
- 好友进房间时会先请求一次完整状态，立刻对齐

### 技术实现（无服务器）

用 **ntfy.sh** —— 一个免费、免注册的公共 pub/sub 服务：

- 订阅：`GET https://ntfy.sh/manman_party_<房间号>/json`（长连接流式读取）
- 发布：`POST https://ntfy.sh/manman_party_<房间号>`（body 是一条 JSON）
- 房间号即 topic，天然隔离；消息不做持久化，退出即散
- 断线自动重连（4 秒），每 25 秒心跳，90 秒无动静的成员自动清理

想换成自己的中继？只需改 `lib/modules/party/party_service.dart` 里的
`relayBase` 常量，任何兼容 ntfy 协议的服务都行。
